EOV Data Producer Metadata

This form allows you to provide metadata describing your Essential Ocean Variables (EOV) "data producer". Submitting an entry via this application will allow it become visible in both the GOOS BioEco Portal and the Ocean Data and Information System (ODIS).

What is a data producer? ▼
A data producer is any entity that produces data, such as a monitoring programme, project, institution, etc. The GOOS BioEco Portal is a portal for data producers to showcase their data and metadata.

All information submitted via this form will become public.

You must have a GitHub account to use this tool as submissions are sent to the GitHub repository.

Submit data producer metadata:

Before proceeding, please note:

  • You do NOT need to submit an entry if it is already visible in Ocean Expert, the GOOS BioEco Portal, ODIS, or the Ocean Info Hub. But please ensure those entries are up to date.
  • This tool is NOT meant to describe metadata for individual datasets. Metadata describing datasets should accompany the dataset when submitted to OBIS. See Data Tools for more details.
Click the "New entry" button to create a new submission. Please do your best to provide as much information as possible. Required fields are marked with an asterisk (*). To update an existing or draft entry, click "Update an entry". When entries are updated, a date is added in a comment. If you are updating a a previously submitted BioEco Portal entry and do not see it available, please reach out to us so we can give you edit access.


Required Metadata ▼

The following metadata fields are required for submission:

  • Name of data producer
  • URL of landing page
  • Frequency of updates to metadata
  • Contact name, email (e.g. helpdesk, general support)
  • Name(s) of relevant EOV(s)

Once submitted, your form entry will be converted into a JSON-LD format and submitted as a GitHub issue to the app's associated GitHub repository. You can preview the output by clicking the "Print JSON" button on the form page.

Technical Details

When you submit the form, your metadata entry is saved as a GitHub issue in the app's repository. The submission is converted into JSON-LD, which is a machine readable format for linked metadata. From each form we generate one JSON-LD file as a graph with three nodes:

  • a Project node that captures general metadata about the data producer, including contact information, EOV details, etc.
  • an Action node to capture sampling detail information, e.g. sampling approach/platform and frequency,
  • a node that only records the frequency of metadata updates, which is used when creating a sitemap downstream

Once your file is submitted, an automatic GitHub Actions workflow then processes the issue to copy it into a folder with a sanitized version of the producer's name in the jsonFiles directory. After this, another automatic GitHub Actions workflow builds a single sitemap that lists all published entries based on the folders within jsonFiles. The files and the sitemap are shared directly with the GOOS BioEco Portal, and with ODIS through the ODIS Catalogue of Sources. The workflow to update entries imported from the previous GeoNode version of the BioEco Portal is slightly different. Each entry has already been imported into the jsonFiles directory, and requires us to give edit permissions to specific GitHub users so the entries will appear in the Update Entry page.
